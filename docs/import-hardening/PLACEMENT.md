## Manifest (`manifest/xlsx_ooxml_summary.json`)

Generated by `node scripts/hardening-manifest.mjs` (deterministic; re-run after adding
files). Covers `workbooks/` + `adversarial/` **plus the repo-native Tier-A goldens in
`samples/iso/`** (the CORE reference workbook lives there). Per file: md5, container
verdict; per sheet: hidden state, reported vs **true** used range, non-empty cell count,
merged ranges, independent header-row candidates (deliberately not the pipeline's own
scorer — non-circular), and an `exceedsEmbedCap` flag against the pipeline's
`MAX_EMBED_ROWS=2000` / `MAX_EMBED_COLS=128`.

Headline facts recorded (2026-07-14): **28/29 workbooks parse, 218 sheets, 29 hidden,
1 sheet exceeds the embed cap** — CORE `Rule References`, **visible, 2280×29** (280 rows
past the AI-path cap; ledger F09/F10), CORE carries **16 hidden sheets** incl.
`Core Rating Specifications (2)` (hidden, 639×73). The extensionless SECURA property
file is a ZIP container whose full parse throws (`End of data reached`) — recorded as
`error` in the manifest, kept deliberately.

## Offline enumeration pass

`node scripts/import-enumerate.mjs` — runs every file in `workbooks/` + `adversarial/`
(plus `mixed/mixed_requests.json` combinations) through the REAL `unifiedImport`
handler (stages 0–7 + normalizeBundle) with global `fetch` stubbed to a deterministic
minimal-valid AI (offline, $0). Records per file: routing, stage counts, plan entity
counts, warnings/errors, and a conservation summary. Results →
`docs/import-hardening/RESULTS/corpus-baseline.json`. Baseline only — **not** wired
into the golden pass/fail gate (IH2 gates it).
