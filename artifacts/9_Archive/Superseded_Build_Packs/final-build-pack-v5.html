What changed from v4 and why

Two structural moves, five hardening additions, three corrections, two effort trims. Structure: PX moves from a solo W3.5 to W4 after P3 and P5, so the HITL export surface and the executive brief actually receive the taste pass (v4 told PX to stay off in-flight files while listing the brief as a target, and never listed the HITL UI at all); P7 moves from a solo post-release wave into W4 paired with PX, timeboxed with a clean-park clause, so the Radar is hardened, verdicted, and released with everything else instead of deploying ungated after the capstone - and the program drops a full wave. Hardening: a history-wide secret scan before the GitHub snapshot (the push carries full git history; HEAD-only scanning misses old leaks and committed run logs); hardened XML parsing with XXE and entity-expansion rejection tests on the two-way import; a cross-tenant negative test on HITL mapping memory; a mandatory import G2-slice re-run before any fleet swap commits (certification freshness); the dormant restore explicitly built, not assumed. Corrections: P3 pinned at Fable xhigh (v4 pinned it three conflicting ways); the P2/P4 boundary becomes an explicit file allowlist (P2's brief endpoint and news-scout wiring are server work that the stated "app/src vs server" split would have collided); a CONTRACTS freeze in orchestration.md so W3 never builds against stale W2 interfaces. Trims that fund the additions: ultrathink off P2 and P5, P5 to effort high. Zero feature, invariant, or finding was cut - see Nothing lost.

Step 1 - Findings

Concrete, evidence-backed, each with its fix location in this pack. HIGH first. Where v4 is right, it says so briefly at the end and moves on.

F1Polish never reaches the flagship surfaces

Evidence: PX sits at W3.5 and is told "if P3 or P5 is live, stay off their in-flight files and take them on a later loop" - but no later loop exists (P6 is next). PX's own surface list includes "the exec brief" (a contradiction), and the HITL capture UI - the most customer-visible new surface in the pack - is not in the list at all.

Risk: the two newest surfaces ship defaulted. Fix: PX moved to W4 after P3/P5; HITL surface and exec brief added to its loop list explicitly.

F2The W2 pair is not collision-free as stated

Evidence: boundary declared "app/src vs server", yet P2 carries three sanctioned server incursions: the brief endpoint ("app/src plus the Home brief endpoint if server-light"), the nightly news-scout wiring (E3 is a server job), and flag persistence that "survives reload". P4 owns "server". Same layer, two writers.

Risk: worktree merge collision or a silently clobbered endpoint. Fix: explicit per-prompt file allowlists published to orchestration.md before first commit; each side declares the other's list FOREIGN; the "if server-light" hedge removed.

F3P3's model is pinned three different ways

Evidence: the matrix says Fable xhigh; the P3 prompt body says "Fable 5 at effort high... escalate to xhigh only if"; the v4 runbook's Fable budget says "P3 at high" and omits PX entirely (stale from a pre-PX draft). An agent obeying the body under-runs the pack's intent on the centerpiece. P3 also lacks the confirm-active-model line that PX has, despite the known Fable-to-Opus silent drop.

Fix: pinned Fable xhigh with a one-line rationale (builds the never-existed Unity transform + overlay semantics + customer-facing HITL); confirm-model line added; runbook rewritten consistent.

F4The GitHub snapshot ships full history; the scan does not

Evidence: R1 says "verify .gitignore and a secret scan first; if any secret or .env is tracked, STOP" - tracked-at-HEAD language. The push carries the entire git history, including any key committed and later deleted, and committed live-run logs under docs/**/RESULTS that can hold endpoints and connection strings. One-way door.

Fix: history-wide gitleaks (or equivalent) plus a RESULTS/log sweep in R1; any hit STOPS with an operator decision (rewrite the snapshot copy or accept).

F5The two-way plug is an unhardened XML parser facing crafted input

Evidence: X5 specifies the adapter seam and fidelity but says nothing about DTDs, external entities, entity expansion, size, or depth - the classic importer holes (XXE, billion laughs) on a feature whose whole point is ingesting external XML.

Fix: binding parser-hardening clause in X5 (DTD off, external entities off, expansion off, size + depth caps) with XXE and expansion rejection tests; P6 attacks it again cold.

F6A fleet swap can silently invalidate IMPORT-CERTIFIED

Evidence: H4b updates the fleet constants "to the best fit per routed task... reusing the import eval harness where it fits" - optional. Certification was earned on the old fleet; swapping the extraction or citation model changes the certified behavior with no fresh proof.

Fix: before ANY import-path model change commits, the import G2 generalization slice must run green on the new model; a red slice reverts the swap and ledgers it. P6 verdict carries a certification-freshness row.

F7Tenant isolation of the new mapping memory is asserted, not proven

Evidence: X6's only test is same-tenant ("a second export prefills from the first"). The leak that matters is cross-tenant: tenant A's overrides prefilling tenant B would be a multi-tenant data leak through a brand-new side channel.

Fix: a negative test in X6 - a different tenant sees ZERO prefill, fail closed - re-proven cold in P6 H4. Same treatment for Radar drafts.

Evidence: handoff finding 4: "Restore is dormant (UI exists; server never returns snapshots)". P4 H2 reads as verify-and-test; an agent can pass it by testing the drawer against a path that returns nothing.

Runbook

Time-to-finish

Five waves, three of them true pairs. The operator pre-warms the W2 worktrees during P1-DONE (plan mode, pushes held), so W2 starts the moment the wave lands. v4's W3.5 solo and post-release W5 are gone: PX and P7 share W4, taking one full wave off the critical path while the Radar gains capstone coverage it never had.

Fable budget shape

Two Fable sessions remain: P3 xhigh and PX xhigh - consistent everywhere in this pack (v4's runbook said "P3 at high" and omitted PX; that drift is fixed). Both sessions confirm the active model first; routing can silently drop to Opus and stay until /model fable. The fresh weekly window (about 8 percent used at handoff) covers both with room to spare.

Limit resilience

Every prompt is restart-safe by construction: the ledger, OPERATING_NOTES, and orchestration.md are the state, and every prompt reconciles at HEAD before building. If a session dies at a usage limit, ask it for a handoff, open a fresh session on the same prompt, and paste the handoff - the P0 pattern. max and ultracode are session-only; re-assert --effort on restarts. Haiku judges are unaffected by the Fable limit.

Judges and plan mode

Every hostile review is a fresh-context, read-only Haiku subagent - decorrelated, never a writer. Open each Opus wave in plan mode, gate the plan against the ledger, then execute. Ultrathink rides only where a decision warrants it: P4, P6, P7.

Parallel safety - explicit

Three pairs: P2 || P4 (published disjoint file allowlists - the brief endpoint, scout wiring, and flag persistence are P2's named server incursions, everything else server-side is P4's), P3 || P5 (export stack vs one isolated route), PX || P7 (existing-path presentation vs new-path feature plus one owned registry line). Worktrees fork at the recorded sha; a single merged main is the integration line; stowaway-check and pathspec commits always apply. Foreign working-tree files are never yours to commit or revert.

Contracts, not vibes

P1-DONE stubs a CONTRACTS section in orchestration.md; P2 and P4 fill it at wave close (Menu/Dialog props, brief shape, flag key and location, provenance envelope). P3 and P5 build against it read-only. A frozen contract changes only with an orchestration note plus a ledger item - the stale-interface bug is designed out.

Release is irreversible

P6 gates RELEASE behind an all-SHIP verdict, scans the FULL history before the GitHub push, refuses to push secrets, proves the scrub with grep (auth.js:100 untouched), re-gates the scrubbed tree before the deploy push, and proves Azure is the only remaining origin with git remote -v. The personal-repo snapshot is intentional history; the scrub is of the codebase going forward.

Voice, parked cleanly

The Live Product Authoring scope sits in the ledger as BACKLOG with its spec intact. The P4 provenance and audit work is the substrate it rides when it unparks - nothing in this pack blocks it.
