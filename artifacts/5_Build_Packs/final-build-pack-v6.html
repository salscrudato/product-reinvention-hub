Parallelism playbook - agents used creatively, safely

Three writers, one main

W-A runs P3, PS, and P5 concurrently on disjoint published allowlists, each in its own worktree under .claude\worktrees, forked from one recorded sha. Single merged main stays the integration line; stowaway-check and pathspec commits always apply; foreign files are never yours.

The push token

Push equals deploy (~7 min) and severs SSE, so pushes serialize: claim the single PUSH row in orchestration.md with your prompt id, push, watch to green, release. If claimed, keep building and batch. After any foreign push lands, rebase your worktree and re-gate before your own push. Three writers, zero deploy collisions.

Read-only swarms

Writers stay singular; readers go wide. PX opens with a parallel Haiku audit swarm - one subagent per surface producing gap lists, axe and contrast results, and screenshot inventories against the bar - so the Fable writer spends its window executing, not surveying. PS uses recon subagents on the Foundry catalog and the existing SSE paths while it plans. P6's verdict is a Haiku scoring swarm.

Contracts over guesses

P2 and P4 already froze the Menu/Dialog props, brief shape, flag key, and provenance envelope. PS adds one more row at close - the SSE protocol and AIResponse component API - so P7 builds its review surface against a frozen interface, not a moving one.
