Operating principles

Five rules the pack enforces. They exist to keep the effort lean: the code may already be efficient, so nothing gets built without a red signal.

Verify, then fix

The external review is static and version-skewed (efb8828 vs 2b1f893). Every finding is a hypothesis until reproduced at current HEAD.

Eval is law

The fitness function decides what gets built, not the review. Metrics: F1, numeric, citations-that-resolve, linkage, conservation, precision-vs-extras.

One writer, many readers

Subagents investigate and judge in parallel; only the main agent edits files. This retires the shared-index git race class entirely.

Monotonic corpus

Every closed bug ships a permanent adversarial fixture. The eval only gets harder; regressions cannot reopen quietly.

Escalate on evidence

Big architecture (evidence IR, rating AST, sectioned PDF) unlocks only when a red fixture demands it or three bugs share it as root cause.

Model plan

Pay for depth exactly where ambiguity lives. Cheap models everywhere else.

THE LOOP (repeat until STOP):
1. ORIENT: reload ledger.json and OPERATING_NOTES.md. Select the open item in the current phase with the highest severity x confidence divided by cost.
2. REPRODUCE: produce a red signal BEFORE editing - a failing fixture, a failing eval metric, or a live repro in accenture-test. No red signal: mark NOT_REPRODUCIBLE with the disproof and move on. Never fix ghosts.
3. FIX: minimal diff at the right layer. Never weaken a check, threshold, or golden to go green. Golden changes ride a separate commit with the diff explained.
4. JUDGE: spawn a fresh hostile-reviewer subagent whose entire context is the diff, the invariants block, the item's acceptance line, and the five standing judge questions below. It never sees your rationale - decorrelated judgment, same principle as the pipeline's cross-family votes. REJECT means revise; two rejects parks the item as ESCALATE with both verdicts attached.
5. GATE (fast, offline): typecheck, lint, test, build; canaries; offline eval slice (--rescore when the change is scoring-side, full offline when extraction-side); linkage and conservation metrics.
6. COMMIT: stowaway-check, git commit --only, message "IH2 [ledger-id]: [title]".
7. LEDGER: close the item with an evidence path, a one-line lesson, and the fixture id. Every closed bug class ships a permanent adversarial fixture. The corpus only grows.
8. WAVE (every 3-5 closed items, or when a fix needs server-side proof): push, wait for deploy, run the phase live slice DETACHED (PowerShell Start-Process on a CRLF/ASCII .cmd written via Set-Content -Encoding Ascii; tee output to a log; watch with tail -f piped to grep --line-buffered that also matches FAILURE signatures; never pipe a probe to head). No pushes mid-live-run. Record results into docs/import-hardening/RESULTS/.
9. SELF-TUNE (every 5 iterations): distill new lessons into OPERATING_NOTES.md, hard cap 40 lines, prune stale lines. Anything worth keeping forever must ALSO exist as a fixture or a gate. Notes are advisory; the eval is law.

PHASES (hard gates, in order; do not start the next early):
PHASE W - WORKBOOKS. Corpus: golden formats plus samples/hardening/workbooks plus adversarial. Gate: F1 at or above 0.95 for every format; numeric at or above 0.98; citations 100% AND resolving against source; attachment/linkage 100% where the source defines limits, deductibles, pricing, and forms; conservation balanced on every file; hidden-sheet and cap-truncation policy explicit and warned; zero unhandled stage errors - across TWO consecutive clean full runs (one full offline, one live CORE slice).
PHASE P - PDFS. Corpus: samples/hardening/pdf. Gate: every fixture classified to the right role or roles, including the two-manuals case (NJ HO plus WA Auto) and any multi-role document; rate-order and manual-rule extractions 100% cited with citations that resolve; facts a policy contract does not state land as UNKNOWN or null with an origin marker, never guessed booleans (this is a schema change: red fixture, tool schema bump, sanitizer update, one commit); conservation balanced.
PHASE M - MIXED. Corpus: samples/hardening/mixed pairings. Gate: cross-artifact merges accounted in the conservation ledger; no double-created entities; the review UI surfaces per-artifact completeness before persist.

ARCH_ESCALATION RULE (anti-overengineering): ledger items classed ARCH_ESCALATION (evidence/assertion IR, FormSeries and FormEdition, rating expression AST, sectioned PDF document map, checkpoint/resume, global scheduler) may start ONLY when (a) a red fixture in the current phase cannot go green without one, or (b) three or more distinct closed bugs share it as root cause. Then build the smallest slice that flips the fixture, behind existing seams (adapter seam, stage-7 projection). Otherwise the item stays parked with its trigger condition written on it.

Runbook - the best setting for this work

Environment

The existing dev lane: local checkout, deploys to app-prodhub-dev, tenant accenture-test. Fleet creds, eval harness, canaries, and the ADO pipeline are already wired there. A fresh environment costs more than it saves.

Inner vs outer loop

Offline eval (--rescore, extracted-JSON replays) is the inner loop measured in minutes. Live runs are the outer loop at wave boundaries only, detached, solo, with tee-to-log discipline.

Why Excel first

Both paths share stage machinery and fleet routing. Hardening workbooks first stabilizes the shared substrate, so Phase P failures are attributable to PDF logic, not a moving baseline. Mixed uploads last to catch interactions.

Long-run discipline

Bash background caps kill 10-minute-plus runs. Detach via PowerShell Start-Process on ASCII/CRLF .cmd files, log to file, monitor with a failure-aware tail.

Agent economics

Fable HIGH once for triage, Opus depth in the loop, Haiku for verdict and all subagents. Never burn Opus on log watching or code archaeology.

Self-improvement, concretely

Two mechanisms only: a monotonic fixture corpus (every bug becomes a permanent test) and a 40-line distilled OPERATING_NOTES.md the loop rereads. No meta-machinery.
